# 用 GitHub Actions 发送学习计划

## 1. 先预览，不发信

```text
python mail/send_plan.py --dry-run --date 2026-10-24
```

脚本只使用 Python 标准库；默认不加参数也只预览。计划保存在 `mail/plan.json`，可修改指定日期的任务。`project_url` 填正式网页网址；留空就不显示网址。

日期默认使用北京时间；没有专门安排的日期使用 `default_tasks`，不会误发 10 月 28 日的旧任务。

## 2. 本人开启 QQ SMTP

登录 QQ 邮箱网页版，在设置中找到 POP3/IMAP/SMTP 服务，按邮箱提示开启 SMTP 并生成授权码。使用的是**授权码**，不是 QQ 登录密码。

授权码不要发到聊天、截图或仓库。

## 3. 配置 GitHub Secrets

打开自己的仓库 → **Settings → Secrets and variables → Actions → Secrets**，新增：

| 名称 | 内容 |
|---|---|
| `QQ_SMTP_USER` | 发信 QQ 邮箱完整地址 |
| `QQ_SMTP_AUTH_CODE` | 本人生成的 SMTP 授权码 |
| `MAIL_TO` | 收件邮箱完整地址，演示时填自己的邮箱 |

## 4. 手动验证一次

进入 **Actions → Daily study mail → Run workflow**：

1. 先保持 `dry_run` 勾选，检查任务预览成功。
2. 再运行一次，取消 `dry_run` 勾选，实际发送。
3. 查看收件箱和垃圾邮件，确认主题日期、中文正文和任务内容。
4. 保留工作流成功截图、实际收到的邮件截图。截图遮住邮箱地址。

SMTP 接受邮件只代表提交成功，收件箱中的实际邮件才是送达证据。

## 5. 开启每天自动发送

在 **Settings → Secrets and variables → Actions → Variables** 新增仓库变量：

```text
ENABLE_DAILY_MAIL = true
```

这是普通变量，不是 Secret。定时任务默认保留但不发送，只有手动验证后开启变量才会自动发信。关闭时将值改成 `false`。

工作流的 `17 0 * * *` 表示 UTC 00:17，也就是北京时间 08:17。文件必须在默认分支；GitHub 定时运行可能延迟，不保证精确到分钟。

交付前至少保留一次 **event = schedule** 的成功记录和对应邮件，不能用手动运行冒充定时成功。若 10 月 28 日后不再需要，可将变量改成 `false`。

## 常见问题

- 缺少配置：检查三个 Secret 名称是否完全一致、值是否为空。
- 登录失败：核实 SMTP 已启用、使用的是授权码；不要把失败信息中的敏感内容公开。
- 工作流被跳过：检查 `ENABLE_DAILY_MAIL` 是否是仓库 Variable 且值为 `true`。
- 只看到预览：实际发送时必须取消 `dry_run`。
- 没有定时记录：确认默认分支有工作流，至少等待一次正常调度；不要不断点击重试造成重复发信。

参考：[GitHub Secrets](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets)、[定时事件](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)。
